# Что нового

## 0.3.0, подготовка к открытому релизу

Игроку

- Повторяющиеся задачи: каждый день, по рабочим дням из распорядка или раз в неделю. В свои дни задача сама встаёт в план, а в плане появился раздел «Повторяются». Пока прошлая не сделана, новая не приходит. Логово похода они не ранят.
- Летопись → «Стереть игру…» убирает игру из браузера вместе с токеном GitHub, а по желанию и гист. Сначала лист предлагает копию в файл. Если гист не удалился, не стирается ничего.
- Тексты вычитаны. «Костёр» теперь значит план на сегодня, «огонь» задачу в работе: «Сейчас у огня», «Оставить у костра на завтра». Числа склоняются («21 задача», «22 письма»), фразы не зависят от пола, правила говорят то же, что делает игра.
- В плане «выше» и «ниже» меняют задачу с соседней видимой. Сделанная задача между ними больше не съедает нажатие.
- Страница и приложение называются «Лагерь у костра», подпись на экране «Домой» «Лагерь».

Сохранение

- Когда запись в GitHub не проходит или в гисте ждёт другая игра, в верхней полосе лагеря появляется значок. Когда сети нет дольше часа, значок спокойнее. Он открывает «Сохранение в GitHub», где сказано, что случилось.
- Игра знает срок токена: от GitHub или год от подключения, его можно поправить. За две недели до конца над меню появляется напоминание с кнопкой «Заменить».
- «Заменить токен»: новый токен того же аккаунта GitHub, гист и игра остаются прежними.
- Ошибка гиста отличает сохранение из более новой версии игры от испорченного.
- Формат сохранения 2: в нём хранятся повторяющиеся задачи. Сохранения 0.2.0 переходят на него сами, а две копии игры на разных устройствах не плодят одну и ту же повторяющуюся задачу.

Доступность

- Кнопки и переключатели не меньше 44×44, у мелких ссылок есть невидимая зона нажатия. У номеров в сцене лагеря она меньше там, где близко соседний номер, поэтому на узком экране один номер не перехватывает нажатия другого.
- Бледный текст стал светлее (4,85:1 на карточках), у красной кнопки 5,4:1.
- Разделы экранов стали заголовками. Верхняя полоса, уровни, дни недели и награды читаются словами, а не значками и римскими цифрами.
- Пока открыт лист, экран под ним недоступен, а Tab ходит только по листу. После закрытия фокус возвращается на кнопку, которая открыла лист. Если кнопка с фокусом пропала («Готово», «Отбой», задача в плане ушла), фокус встаёт на ближайший заголовок или кнопку, а не в начало страницы.
- Сообщения внизу экрана диктор читает всегда, вместе с кнопкой «Вернуть». На узком экране кнопка «К огню» для него называется полностью.
- На странице входа поле пароля всегда получает фокус.
- `docs/screen-reader-check.md`: что проверить руками с VoiceOver и TalkBack.

Проверки

- Автотесты экранов на Playwright (`npm run e2e`): 13 сценариев на собранном сайте в настоящем браузере. День от знакомства до отбоя идёт на маленьком телефоне, обычном и компьютере, остальные на телефоне: запуск без сети, повторяющиеся задачи, GitHub с поддельным API, «Стереть всё», axe на всех экранах и листах, клавиатура, страница входа с паролем.
- Публикация на GitHub Pages прогоняет их на сборке с паролем и не выходит, если что-то упало. Отчёты с введённым паролем на GitHub не выкладываются.
- 66 автотестов логики вместо 43: повторяющиеся задачи, слияние их с двух устройств, срок и замена токена, удаление гиста, переход со старого сохранения.
- Playwright 1.63.0 и axe-core 4.13.0 только для тестов, на сайт они не попадают.

## 0.2.0, закрытая бета

Сайт

- Сайт закрыт паролем: код игры зашифрован, пароль задаётся секретом `LAGER_PASSWORD` в репозитории. Пароль можно запомнить на устройстве и забыть в Летописи → «О приложении».
- Без пароля публикация на GitHub Actions падает, поэтому открытым сайт по ошибке не выйдет.
- Игра открывается без сети уже после первого визита. Когда выходит новая версия, над меню появляется строка «Вышла новая версия» с кнопкой «Обновить».
- На странице стоит Content-Security-Policy: скрипты только свои, запросы только к GitHub.
- Файл публикации лежит на своём месте, в `.github/workflows/deploy.yml`. Папка `ci/` больше не нужна.

Сохранение

- Если два устройства записали в GitHub почти одновременно, задачи обеих сторон больше не теряются.
- Нечитаемое сохранение не затирается. Вместо игры открывается экран, где его можно скачать, взять игру из GitHub, загрузить копию из файла или начать заново.
- У сохранения есть номер формата и место для переходов между версиями. Сохранение из более новой версии игры старая страница не трогает и просит обновиться.
- Если браузер не дал записать игру, над меню появляется предупреждение. Без GitHub игра раз в неделю напоминает сохранить копию в файл.
- Игра просит у браузера постоянное хранилище, а на iPhone подсказывает добавить её на экран «Домой».
- У токена GitHub появилось предупреждение и ссылка, где его отозвать.

Игроку

- Знакомство из четырёх карточек при первом запуске. В Летописи появились «Правила» (числа берутся прямо из правил игры) и «О приложении».
- Экран «Что-то сломалось» с отчётом для разработчика. Действие, упавшее с ошибкой, не портит игру: она возвращается к последней записи.
- Номер версии виден в Летописи и в отчёте.
- На низких телефонах сцена лагеря уменьшается, чтобы номера не уходили под верхнюю полосу, а строка «ещё N у костра» была видна. По бокам тогда виден размытый лес.
- Подсказка в пустом отряде.

Правила

- Отмена «Готово» снимает съеденную лягушку дня и упокоенную нежить.
- Отпущенную задачу можно вернуть: кнопкой «Вернуть» в сообщении сразу после этого или позже в Королевстве → «Отпущенные».
- Распорядок, в котором путаются смены (конец работы раньше начала, отбой раньше конца работы), не сохраняется, а под полями объясняется почему.

Прочее

- vitest 4.1.12 закрывает уязвимость, которую находил `npm audit`.
- 43 автотеста: добавлены одновременная запись, нечитаемое сохранение, сбой записи, откат упавшего действия, возврат из GitHub, отмена лягушки и нежити, возврат отпущенной задачи, проверка распорядка.
